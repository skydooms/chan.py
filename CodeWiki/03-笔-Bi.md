# 03 · 笔（Bi）

笔是缠论结构的第一个「有意义」的元素：由两个方向相反的合并 K 线（分型）连接而成。本篇覆盖 `CBi`（笔对象）、`CBiList`（画笔状态机）、`CBiConfig`（笔参数），以及笔的力度度量（背驰计算的基础）。

## 1. 笔对象 `CBi`

### 1.1 构造与方向

```python
CBi(begin_klc: CKLine, end_klc: CKLine, idx: int, is_sure: bool)
```

方向**不是传进来的**，而是由起始合并 K 线的分型推出（[CBi.set](file:///workspace/Bi/Bi.py#L101-L111)）：

- `begin_klc.fx == BOTTOM` → `BI_DIR.UP`
- `begin_klc.fx == TOP` → `BI_DIR.DOWN`
- 其他 → 抛 `CChanException(BI_ERR)`

构造末尾调用 `check()`（[#L92-L99](file:///workspace/Bi/Bi.py#L92-L99)）：

- 下降笔：`begin_klc.high > end_klc.low`
- 上升笔：`begin_klc.low < end_klc.high`

### 1.2 成员一览

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `idx` | int | 笔序号 |
| `dir` | `BI_DIR` | 方向 |
| `type` | `BI_TYPE` | 恒为 `STRICT`；开源版未使用（完整版用于区分次高点笔、跳空笔等） |
| `is_sure` | bool | 是否已确定（虚笔为 False） |
| `used_to_be_sure` | bool | 「曾经确定过」，用于特征序列判断稳定性 |
| `sure_end` | `List[CKLine]` | 虚笔被延展时，记录曾经确定过的端点（回滚用） |
| `begin_klc` / `end_klc` | `CKLine` | 起止合并 K 线 |
| `seg_idx` | int | 所属线段编号（由 `cal_seg` 回填） |
| `parent_seg` | `CSeg` | 所属线段对象 |
| `bsp` | `CBS_Point` | 若笔尾是买卖点则指回该买卖点 |
| `pre` / `next` | `CBi` | 前后笔 |

### 1.3 取值方法（最常用的一批）

| 方法 | 含义 |
| --- | --- |
| `get_begin_val()` / `get_end_val()` | 笔起点/终点**价格**：上升笔取 low→high，下降笔取 high→low |
| `get_begin_klu()` / `get_end_klu()` | 笔起点/终点**原始 K 线**：上升笔起点取该 KLC 的最低点 klu，终点取最高点 klu；下降笔相反 |
| `_high()` / `_low()` | 整笔的极值（上升笔 high=end_klc.high） |
| `_mid()` | 笔的中位价 `(high+low)/2` |
| `amp()` | 笔的绝对振幅 `abs(end_val - begin_val)` |
| `get_klu_cnt()` | 笔覆盖的原始 K 线根数 |
| `get_klc_cnt()` | 笔覆盖的合并 K 线根数（内部有断言校验端点归属） |
| `klc_lst` / `klc_lst_re` | 正序/倒序迭代笔内合并 K 线（生成器） |
| `is_up()` / `is_down()` | 方向判断（带缓存） |

> **易混淆点**：`get_begin_klu()` 不是「第一根合并 K 线里的第一根 K 线」，而是「第一根合并 K 线中极值所在的 K 线」。这是缠论「笔端点取极值」的直接体现，绘图和背驰计算都依赖它。

除 `set()/check()/clean_cache()` 外，上述取值全部用 `@make_cache` 缓存，因此**任何改变端点/方向的操作都必须 `clean_cache()`**（源码中 `update_new_end`、`set` 都这么做了）。

### 1.4 虚笔的延展与回滚

```python
bi.update_virtual_end(new_klc)      # 尾部继续创新高/新低，把当前端点存入 sure_end，标记 is_sure=False
bi.restore_from_virtual_end(klc)    # 回滚到某个曾经确定的端点，恢复 is_sure=True
bi.append_sure_end(klc)             # 记录一个曾经确定的端点
```

见 [Bi.py#L169-L187](file:///workspace/Bi/Bi.py#L169-L187)。这套机制支撑了「当前帧」语义：最后一笔在行情延续时会不断延展，但其「曾经确定」的端点被保留下来，一旦反向分型成立即可回滚成实笔。

### 1.5 笔的力度度量 `cal_macd_metric`

买卖点背驰判断的统一入口（[Bi.py#L189-L332](file:///workspace/Bi/Bi.py#L189-L332)），由 `macd_algo` 配置选择：

| `macd_algo` | 实现 | 含义 |
| --- | --- | --- |
| `peak`（默认） | `Cal_MACD_peak` | 笔内同向 MACD 柱的**最大绝对值** |
| `area` | `Cal_MACD_half` | 从笔端点起、**同向连续**的 MACD 柱面积；`is_reverse=True` 时从终点反向累计 |
| `full_area` | `Cal_MACD_area` | 整笔范围内所有同向 MACD 柱面积之和 |
| `diff` | `Cal_MACD_diff` | 笔内 MACD 柱最大值与最小值之差 |
| `slope` | `Cal_MACD_slope` | 归一化斜率：`(终点价-起点价)/终点价/K线数` |
| `amp` | `Cal_MACD_amp` | 归一化涨跌幅 |
| `amount` / `volumn` | `Cal_MACD_trade_metric` | 笔内成交额 / 成交量总和 |
| `amount_avg` / `volumn_avg` / `turnrate_avg` | 同上 `cal_avg=True` | 笔内平均值（除以 K 线根数） |
| `rsi` | `Cal_Rsi` | 笔内 RSI 极值（下降笔取 `10000/(min+1e-7)` 以保持「越大力度越强」的一致性） |

两个实现细节：

1. 所有面积类指标都加了 `1e-7` 的底，避免 0 做分母；
2. `Cal_MACD_half_obverse` 遇到「MACD 柱符号翻转」即 `break`，只累计与端点同向的一段——这就是「半面积」的含义。

`Cal_MACD_trade_metric` 遇到任一 K 线缺量/额数据会整体返回 `0.0`（[#L324-L332](file:///workspace/Bi/Bi.py#L324-L332)），使用时要注意数据完整性。

## 2. 画笔状态机 `CBiList`

`CBiList` 维护 `bi_list: List[CBi]`、`last_end`（最后一笔的尾部 KLC）与 `free_klc_lst`（第一笔成立前的缓存）。

### 2.1 入口：`update_bi`

```python
def update_bi(self, klc, last_klc, cal_virtual) -> bool
```

- `klc`：**倒数第二根**合并 K 线（其分型已在 `add_single_klu` 中被确认）；
- `last_klc`：**最后一根**合并 K 线；
- `cal_virtual`：是否同时尝试虚笔（等于 `trigger_step`）。

内部先 `update_bi_sure(klc)`，再（可选）`try_add_virtual_bi(last_klc)`，返回「是否有新笔/虚笔变化」（[BiList.py#L48-L56](file:///workspace/Bi/BiList.py#L48-L56)）。

### 2.2 实笔推进 `update_bi_sure`

[BiList.py#L86-L103](file:///workspace/Bi/BiList.py#L86-L103) 的分支顺序很关键：

```mermaid
flowchart TD
    A["update_bi_sure(klc)"] --> B[记录 tmp_end = 最后一笔终点 klu idx]
    B --> C[delete_virtual_bi 先撤掉虚笔]
    C --> D{klc.fx == UNKNOWN?}
    D -- 是 --> E[返回：虚笔终点是否变化]
    D -- 否 --> F{还没有任何笔?}
    F -- 是 --> G[try_create_first_bi]
    F -- 否 --> H{klc.fx == last_end.fx?}
    H -- 是 --> I["try_update_end(同向分型)<br/>延展最后一笔端点"]
    H -- 否 --> J{can_make_bi(klc, last_end)?}
    J -- 是 --> K[add_new_bi 新增一笔]
    J -- 否 --> L["update_peak(klc)<br/>尝试用新极值替换倒数第二笔"]
    L --> M[返回是否有变化]
```

其中：

- **`try_create_first_bi`**：第一笔的起点需要「回溯」——把当前分型与 `free_klc_lst` 里方向相反的候选逐一尝试，成立才生成第一笔；否则继续缓存（[#L36-L46](file:///workspace/Bi/BiList.py#L36-L46)）；
- **`try_update_end`**：同向分型且创新高/新低 → 更新最后一笔终点（实笔走 `update_new_end`，虚笔走 `update_virtual_end`）；
- **`update_peak`**：当新分型不能直接成笔时，尝试「推翻最后一笔，让倒数第二笔直接连到更极端的点」，前提是 `can_update_peak` 全部满足（[#L58-L84](file:///workspace/Bi/BiList.py#L58-L84)）。

### 2.3 笔的成立条件 `can_make_bi`

[BiList.py#L178-L186](file:///workspace/Bi/BiList.py#L178-L186)：

```python
can_make_bi = 满足跨度 and 分型合法 and (尾部是极值)
```

**① 跨度 `satisfy_bi_span`**（[#L149-L176](file:///workspace/Bi/BiList.py#L149-L176)）：

| 配置 | 条件 |
| --- | --- |
| `bi_algo = "fx"` | **不检查跨度**，顶底分型即成笔 |
| `bi_strict = True`（默认） | 两个分型之间至少跨 **4 根合并 K 线**（`span >= 4`） |
| `bi_strict = False` | `span >= 3` **且** 中间原始 K 线总数 `>= 3` |

`span` 由 `get_klc_span` 计算；当 `gap_as_kl=True` 时，区间内的**跳空**会被额外计为 1 根 K 线（[#L165-L176](file:///workspace/Bi/BiList.py#L165-L176)），用来兼容「跳空缺口当一根 K 线」的流派。

**② 分型合法**：`last_end.check_fx_valid(klc, bi_fx_check, for_virtual)`，四种模式见 [02-K线与合并](02-K线与合并.md#51-check_fx_valid-的四种模式)。

**③ 尾部极值**：当 `bi_end_is_peak=True`（默认）时，要求 `end_is_peak(last_end, klc)`——即从起点到终点之间，不能出现比终点更极端的价（[#L216-L235](file:///workspace/Bi/BiList.py#L216-L235)）。

> 三个条件的组合正是 `CChanConfig` 里 `bi_strict` / `bi_fx_check` / `bi_end_is_peak` / `gap_as_kl` 四个参数影响画笔结果的路径。quick_guide 建议绝大多数场景直接用默认值。

### 2.4 虚笔 `try_add_virtual_bi`

[BiList.py#L120-L141](file:///workspace/Bi/BiList.py#L120-L141)：

1. 若最后一笔仍创新高/新低 → 直接 `update_virtual_end` 延展；
2. 否则**倒着**遍历已有 KLC（`_tmp_klc.pre`），寻找可以成笔的分型：能成笔就 `add_new_bi(..., is_sure=False)`，能更新极值就 `update_peak(for_virtual=True)`。

虚笔让「当前帧」总能给出一个完整结构，代价是这笔的终点可能变化。`delete_virtual_bi`（[#L105-L118](file:///workspace/Bi/BiList.py#L105-L118)）负责在每次推进前撤掉虚笔：

- 若虚笔有 `sure_end` 历史 → 先回滚到第一个确定端点，再把后续端点**依次转成实笔**；
- 否则直接删除；
- 最后重置 `last_end` 与 `next` 指针。

### 2.5 增量正确性的保障

- 已确定的笔**永不回改**（`is_sure=True` 后只可能在其后追加）；
- 每次推进都先撤虚笔 → 推进实笔 → 再补虚笔，保证两种计算模式（静态/增量）结果一致（quick_guide「一致性」章节的约定）。

## 3. 笔配置 `CBiConfig`

源码：[Bi/BiConfig.py](file:///workspace/Bi/BiConfig.py#L5-L30)

| 参数 | 类型 | `CBiConfig` 默认 | `CChanConfig` 传入的默认 | 作用 |
| --- | --- | --- | --- | --- |
| `bi_algo` | str | `normal` | `normal` | `normal` 按定义画笔；`fx` 有分型即成笔 |
| `is_strict` | bool | `True` | `True` | 严格笔（跨度 4）vs 非严格笔（跨度 3 + K 线数 3） |
| `bi_fx_check` | str | `half` | **`strict`** | 分型检查方法 `strict/totally/loss/half` |
| `gap_as_kl` | bool | `True` | **`False`** | 跳空是否当作一根 K 线 |
| `bi_end_is_peak` | bool | `True` | `True` | 笔终点是否为区间极值 |
| `bi_allow_sub_peak` | bool | `True` | `True` | 是否允许次高点成笔 |

> ⚠️ 注意：`CBiConfig` 类自身默认值与 `CChanConfig` 实际传入的默认值**不一致**（`bi_fx_check` 与 `gap_as_kl`）。日常使用以 `CChanConfig` 为准，因为 `CKLine_List` 永远从 `CChanConfig.bi_conf` 取配置。直接实例化 `CBiConfig()` 只在你单独测试画笔逻辑时才会遇到另一套默认值。

`bi_fx_check` 字符串到枚举的映射在 `CBiConfig.__init__` 中完成，非法值抛 `PARA_ERROR`。

## 4. 常见调整与影响面

| 你的诉求 | 应调整 | 副作用 |
| --- | --- | --- |
| 笔太少 / 太迟钝 | `bi_strict=False`，或 `bi_fx_check="loss"/"half"` | 笔变多，线段与中枢随之变化 |
| 笔太多 / 噪音大 | `bi_fx_check="strict"`（默认）、`bi_end_is_peak=True` | 笔更少更「干净」，但确认更晚 |
| 想让跳空单独算一根 K 线 | `gap_as_kl=True` | 跨度更容易满足，笔更容易成立 |
| 只想要最朴素的「分型即成笔」 | `bi_algo="fx"` | 跨度条件被完全跳过 |
| 允许次高点成笔 | `bi_allow_sub_peak=True`（默认） | 极值替换更激进 |

调整后建议打开 `plot_bi` 与 `plot_kline_combine` 目视检查，或者打开 `plot_eigen` 辅助分析线段（见 [09-可视化](09-可视化.md)）。

## 5. 本篇小结

- 笔的方向由起点合并 K 线的分型决定，端点取「极值 K 线」而非首根 K 线；
- 一笔成立 = 跨度满足 + 分型合法 + 端点是区间极值，三个条件分别由 `bi_strict`、`bi_fx_check`、`bi_end_is_peak` 控制；
- 虚笔是「当前帧」的产物，`sure_end` 历史保证可回滚；
- `cal_macd_metric` 是背驰判断的统一度量接口，买卖点模块直接复用。
