## 1. 分层视图

整个项目是一台「K 线 → 缠论结构」的流水线，自上而下 5 层：

三条不变式：

1. **只有 `CChan` 一个编排者**，它持有「级别 → `CKLine_List`」，所有元素都挂在对应级别容器上；
2. **结构计算单向递归推进**：K 线 → 笔 → 线段 → 中枢 → 买卖点，上层只消费下层产物；
3. **指标结果一次写回 K 线**，上层直接读 `klu.macd` 等，不重复计算。

### 2.1 多级别递归的关键机制

`load_iterator(lv_idx, parent_klu, step)` 等价于「**按父级别 K 线切分次级别 K 线**」：

- 从当前级别取一根 klu；
- 若它的时间 **超过** 当前父 klu 的结束时间，就放入 `klu_cache[lv_idx]` 并退出本轮，等父级别推进后再处理（[Chan.py#L258-L260](file:///workspace/Chan.py#L258-L260)）；
- 否则加入本级 `CKLine_List`，然后**递归调用下一级别**，消费掉落在它时间范围内的所有次级别 klu；
- 递归返回后 `check_kl_align` 校验次级别是否为空，不一致则累计到 `kl_inconsistent_detail`。

由此得到三个结论：

- `lv_list[0]` 是驱动级别，最高级别每前进一根，次级别被消费一组；
- 次级别可以一次喂很多，框架用 `klu_cache` 自动按父级别时间截断；
- `parent_klu.add_children(klu)` / `klu.set_parent(parent_klu)` 建立跨级别引用（`sub_kl_list` / `sup_kl`），供区间套与绘图下钻。

这就是「线段的分段」「线段买卖点」几乎零成本复用的原因。

## 4. 模块依赖矩阵

`←` 表示依赖；对 `Common` 的普遍依赖省略。

### 4.1 循环依赖如何被打断

源码里大量「函数内 import」是刻意设计：

- [KLine_Unit.__init__](file:///workspace/KLine/KLine_Unit.py#L36-L37)：`CKLine` 写在方法内，因为 `CKLine` 反向继承 `CKLine_Combiner[CKLine_Unit]`；
- [CBi.__init__](file:///workspace/Bi/Bi.py#L26-L30)：`CSeg`、`CBS_Point` 只用于类型标注，放方法内；
- [CCombine_Item.__init__](file:///workspace/Combiner/Combine_Item.py#L5-L8)：合并器需同时适配 `CBi/CSeg/CKLine_Unit`；
- [CSeg.__init__](file:///workspace/Seg/Seg.py#L15-L44)：`CZS`、`CBS_Point` 方法内 import；
- [KLine_List.get_seglist_instance](file:///workspace/KLine/KLine_List.py#L19-L32)：按 `seg_algo` 延迟选择线段算法。

扩展时请沿用该约定，否则容易踩 import cycle。

## 5. 两种计算模式

| | 静态模式（默认） | 增量 / 回放模式 |
| --- | --- | --- |
| 开关 | `trigger_step=False` | `CChanConfig({"trigger_step": True})` |
| 构造时是否计算 | 立即跑完 | **不做任何计算** |
| 驱动方式 | `CChan.__init__` 内部 `for _ in self.load()` | `chan.step_load()` / `chan.trigger_load(...)` |
| 每次新增 K 线 | — | 只重算尾部不确定部分，然后 `cal_seg_and_zs()` |
| 适用 | 离线分析、选股 | 回测、实盘、逐帧动画 |

两者共享同一套 `load_iterator`，差异在于：

- `step_load()` 断言 `trigger_step`，先 `do_init()` 清空，再 `load(step=True)`，用 `skip_step` 跳过前 N 帧（[Chan.py#L120-L130](file:///workspace/Chan.py#L120-L130)）；
- `trigger_load(inp)` 允许外部直接喂 `Dict[KL_TYPE, List[CKLine_Unit]]`（[Chan.py#L132-L151](file:///workspace/Chan.py#L132-L151)）；
- `CKLine_List.step_calculation = config.trigger_step`，决定每根 K 线后是否立刻 `cal_seg_and_zs()`（[KLine_List.py#L52](file:///workspace/KLine/KLine_List.py#L52)、[#L132-L135](file:///workspace/KLine/KLine_List.py#L132-L135)）。

### 5.1 `is_sure` 语义（贯穿全项目）

- `is_sure=False` 的元素**只出现在序列两端**，中间部分一旦确认不再变化；
- 尾部不确定的笔/线段/中枢/买卖点会随新 K 线被修正甚至消失——这就是「信号为什么会消失」的根因；
- 画图中实线 = 确定，虚线 = 不确定。

对应实现：虚笔 [try_add_virtual_bi](file:///workspace/Bi/BiList.py#L120-L141)、虚段 [collect_left_seg](file:///workspace/Seg/SegListComm.py#L112-L119)、中枢安全位置 [CZSList](file:///workspace/ZS/ZSList.py#L38-L50)、买卖点回滚 [clear_store_end](file:///workspace/BuySellPoint/BSPointList.py#L44-L60)。

## 6. 关键设计模式

| 模式 | 体现 | 收益 |
| --- | --- | --- |
| 模板方法 | `CSegListComm` 定义 `add_new_seg/collect_left_seg`，子类实现 `update()` | 三种划段算法共用骨架 |
| 泛型参数化 | `CKLine_Combiner[T]`、`CSeg[LINE_TYPE]`、`CBSPointList[LT, LLT]` | 同一逻辑服务「笔」与「线段」 |
| 适配器 | `CCombine_Item` 把三种元素归一成 `high/low/time` | 合并器不感知具体类型 |
| 装饰器（描述符） | `@make_cache` | 热点取值按实例缓存，`clean_cache()` 精确失效 |
| 工厂 | `GetStockAPI()`、`get_seglist_instance()`、`GetMetricModel()` | 数据源、线段算法、指标可插拔 |
| 一次写回 | `CKLine_Unit.set_metric()` | 指标只算一次，全项目复用 |

`make_cache` 要求被装饰方法签名为 `(self)` 且无其他参数，缓存存在实例的 `_memoize_cache`，key 是函数对象字符串（[Common/cache.py](file:///workspace/Common/cache.py#L1-L34)）。元素一旦被修改（`try_add`、`update_new_end`、`set_pre/set_next`）必须 `clean_cache()`，否则读到旧值——这是源码中高频 `clean_cache()` 调用的原因。
