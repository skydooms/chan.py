## 1. 中枢对象 `CZS`

```python
CZS(lst: Optional[List[LINE_TYPE]], is_sure=True)
```

`LINE_TYPE` 是 `CBi` 或 `CSeg`——因为有 `CCombine_Item` 同款的取值约定（`get_begin_klu()` / `get_end_klu()` / `_high()` / `_low()`），中枢天然支持两种粒度。

### 1.1 构造过程

[ZS.py#L14-L42](file:///workspace/ZS/ZS.py#L14-L42)：

```python
self.__begin    = lst[0].get_begin_klu()   # 中枢起点：第一笔的起始 K 线
self.__begin_bi = lst[0]                   # 中枢内部第一笔
self.update_zs_range(lst)                  # 中枢区间
for item in lst: self.update_zs_end(item)  # 逐笔推进终点 + 极值
self.__bi_in  = None   # 进中枢的笔
self.__bi_out = None   # 出中枢的笔
self.__bi_lst = []     # 中枢内部笔（由 update_zs_in_seg 填充）
```

### 1.2 区间定义

`update_zs_range`（[#L89-L93](file:///workspace/ZS/ZS.py#L89-L93)）：

```python
low  = max(bi._low()  for bi in lst)   # 各笔低点的最大值
high = min(bi._high() for bi in lst)   # 各笔高点的最小值
mid  = (low + high) / 2
```

即**所有构成笔的公共重叠区间**。`update_zs_end` 同时维护：

- `end` / `end_bi`：中枢最后一笔及其结束 K 线；
- `peak_low` / `peak_high`：中枢所涉所有笔的**最低低点 / 最高高点**（不是重叠区间，是整体范围）。

### 1.3 成员速查

| 成员 | 说明 |
| --- | --- |
| `begin` / `end` | 起止 `CKLine_Unit` |
| `begin_bi` / `end_bi` | 起止笔（或段） |
| `low` / `high` / `mid` | 中枢区间 |
| `peak_low` / `peak_high` | 中枢整体极值 |
| `bi_in` / `bi_out` | 进入/离开中枢的那一笔（在中枢区间外） |
| `bi_lst` | 中枢内部笔列表 |
| `sub_zs_lst` | 发生合并时的子中枢列表 |
| `is_sure` | 是否确定 |

`is_one_bi_zs()`（[#L95-L97](file:///workspace/ZS/ZS.py#L95-L97)）判断「只有一笔的中枢」——这种中枢只在 `one_bi_zs=True` 时才会生成，且在很多买卖点判定中会被排除。

### 1.4 延伸 `try_add_to_end`

[#L148-L154](file:///workspace/ZS/ZS.py#L148-L154)：

```python
if not self.in_range(item):       # 新区间与中枢无重叠 → 不能延伸
    return False
if self.is_one_bi_zs():           # 一笔中枢首次延伸时，需要把区间重新算成两笔重叠
    self.update_zs_range([self.begin_bi, item])
self.update_zs_end(item)
return True
```

`in_range(item)` 用 `has_overlap(low, high, item._low(), item._high())` 判定（[#L156-L157](file:///workspace/ZS/ZS.py#L156-L157)）。

### 1.5 合并 `combine`

[#L115-L146](file:///workspace/ZS/ZS.py#L115-L146)：

前置拒绝条件：

1. 目标中枢是「一笔中枢」→ 不合并；
2. 两个中枢 `begin_bi.seg_idx` 不同 → **不合并（不跨段）**。

两种模式：

| `zs_combine_mode` | 判定 |
| --- | --- |
| `zs`（默认） | 两中枢的**重叠区间**有重叠（`equal=True`，即相切也算） |
| `peak` | 两中枢的**整体极值区间**（`peak_low~peak_high`）有重叠 |

合并 `do_combine`（[#L134-L146](file:///workspace/ZS/ZS.py#L134-L146)）：

- 第一次合并时，先把**自身快照**放进 `sub_zs_lst`，再放入对方，保留「合并前长什么样」；
- 区间取 `min(low)` / `max(high)`（并集，因此合并后中枢会变宽）；
- `peak_*` 取并集，`end`/`end_bi`/`bi_out` 取后者。

> 注意 `sub_zs_lst` 在绘图时用于画「子中枢」（`plot_zs` 的 `sub_linewidth`），也是 `CZS_meta` 递归的来源。

### 1.6 背驰判断 `is_divergence`

[#L162-L174](file:///workspace/ZS/ZS.py#L162-L174)：

```python
if not self.end_bi_break(out_bi):        # ① 离开中枢的笔必须真的突破中枢边界
    return False, None
in_metric  = bi_in.cal_macd_metric(config.macd_algo, is_reverse=False)
out_metric = (bi_out or out_bi).cal_macd_metric(config.macd_algo, is_reverse=True)
if config.divergence_rate > 100:          # ② 背驰率 > 100 视为「保送」
    return True, out_metric / in_metric
return out_metric <= config.divergence_rate * in_metric, out_metric / in_metric
```

- `end_bi_break`（[#L193-L198](file:///workspace/ZS/ZS.py#L193-L198)）：出中枢的笔（下降笔要跌破 `low`，上升笔要涨破 `high`）；
- 返回值第二项是「背驰度」，会被写进买卖点特征 `divergence_rate`（注意是 `out/in`，**越小越背驰**）；
- `divergence_rate > 100` 是给「只想看结构、不筛背驰」的用户准备的暴力开关（`main.py` 里用的 `float("inf")` 就是它）。

### 1.7 出笔是否极值 `out_bi_is_peak`

[#L200-L214](file:///workspace/ZS/ZS.py#L200-L214)：遍历中枢内笔，若存在比 `bi_out` 更极端的笔则返回 `(False, None)`；否则返回 `(True, 最小差距比例)`。用于 `bs1_peak` 配置（一类买卖点是否必须在中枢极值处）。

### 1.8 复制

`make_copy()` + `init_from_zs()`（[#L176-L191](file:///workspace/ZS/ZS.py#L176-L191)）是给合并逻辑用的浅拷贝构造函数（不重新计算区间，直接搬运字段）。

## 2. 中枢列表 `CZSList`

### 2.1 状态

| 成员 | 说明 |
| --- | --- |
| `zs_lst: List[CZS]` | 已生成的中枢 |
| `free_item_lst` | **候选缓存**：还没凑够重叠笔的「游离笔」 |
| `last_sure_pos` | 最后一个确定线段起始笔的 idx |
| `last_seg_idx` | 最后一个确定线段的编号 |
| `config: CZSConfig` | 中枢配置 |

`free_item_lst` 是增量计算的关键：中枢需要至少 2 笔重叠，第 1 笔先放缓存，第 2 笔才可能成型。

### 2.2 单笔推进 `update`

[#L52-L57](file:///workspace/ZS/ZSList.py#L52-L57)：

```python
if len(free_item_lst) == 0 and self.try_add_to_end(bi):
    # peak 合并模式下会命中：新笔直接并入最后一个中枢
    self.try_combine()
    return
self.add_to_free_lst(bi, is_sure, "normal")
```

`add_to_free_lst`（[#L38-L50](file:///workspace/ZS/ZSList.py#L38-L50)）：

1. 若缓存末尾与新笔 idx 相同（笔端点被更新过），先弹掉旧的；
2. 追加新笔，尝试 `try_construct_zs(free_item_lst, ...)`；
3. 构造成功且 `begin_bi.idx > 0`（**中枢不能从第 0 笔开始**）→ 加入 `zs_lst`、清空缓存、尝试合并。

### 2.3 构造条件 `try_construct_zs`

[#L73-L89](file:///workspace/ZS/ZSList.py#L73-L89)：

| `zs_algo` | 取哪些笔 | 条件 |
| --- | --- | --- |
| `normal` | 最后 2 笔（`one_bi_zs=True` 时允许 1 笔） | `min(high) > max(low)` 才算有重叠 |
| `over_seg` | 最后 3 笔 | 且第 1 笔不能与所属线段同向，否则丢弃并返回 `None` |

### 2.4 三种中枢算法 `cal_bi_zs`

[#L91-L130](file:///workspace/ZS/ZSList.py#L91-L130)：

```python
while zs_lst 且 最后一个中枢的起始笔 >= last_sure_pos: pop()   # ① 回滚尾部中枢
```

| 算法 | 行为 |
| --- | --- |
| `normal`（默认，段内中枢） | 以**线段**为单位，逐段把段内「与段方向相反」的笔喂入；最后一段之后的剩余笔也按反向笔再喂一遍（`is_sure=False`） |
| `over_seg`（跨段中枢） | 从最后一个中枢的下一笔开始，逐笔 `update_overseg_zs`，允许中枢跨越线段边界 |
| `auto` | 确定的线段用 `normal`，不确定部分退化为 `over_seg` |

三者最终都会 `update_last_pos(seg_lst)` 记录进度。

`add_zs_from_bi_range`（[#L62-L71](file:///workspace/ZS/ZSList.py#L62-L71)）的 `deal_bi_cnt` 细节很重要：段内第一根反向笔用 `add_to_free_lst`（防止误延伸到上一段的中枢），后续走 `update`。

### 2.5 跨段延伸 `update_overseg_zs`

[#L132-L140](file:///workspace/ZS/ZSList.py#L132-L140)：

- 若已有中枢且缓存为空，且新笔与前中枢 `end_bi` 距离 ≤ 1、并且与「下一笔」有重叠 → 尝试并入中枢；
- 若新笔本身落在中枢区间内且距离 ≤ 1 → 直接忽略（属于中枢震荡）；
- 否则放入缓存重新构造。

### 2.6 合并 `try_combine`

[#L157-L161](file:///workspace/ZS/ZSList.py#L157-L161)：`while len>=2 and 最后两个能合并: 丢掉最后一个`。因为 `combine` 会把内容并进「前一个」，所以删除的是后一个。

### 2.7 增量回滚

- `update_last_pos`：从尾部找第一个 `is_sure` 的线段，记录其 `start_bi.idx` 作为「安全位置」；
- `cal_bi_zs` 开头会把所有 `begin_bi.idx >= last_sure_pos` 的中枢弹出，然后重算这部分。

这就是中枢能在「当前帧」里被修正甚至消失的实现方式。

## 3. 中枢配置 `CZSConfig`

[ZS/ZSConfig.py](file:///workspace/ZS/ZSConfig.py#L1-L6)

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `need_combine` | `True` | 是否合并相邻重叠中枢 |
| `zs_combine_mode` | `"zs"` | `zs`：区间重叠才合并；`peak`：整体极值区间重叠即合并 |
| `one_bi_zs` | `False` | 是否保留「一笔中枢」 |
| `zs_algo` | `"normal"` | `normal` 段内 / `over_seg` 跨段 / `auto` 自动 |

### 3.1 `zs_algo` 怎么选

- **段内中枢（normal）**：符合「中枢在段内形成」的传统读法，买卖点判定更严格，推荐默认；
- **跨段中枢（over_seg）**：允许中枢横跨线段，适合看大级别震荡；注意源码要求 `one_bi_zs=False`（`cal_bi_zs` 里有断言）；
- **auto**：想兼顾两者时使用，确定部分用 normal、未确定部分用 over_seg。

切换算法会显著改变 `zs_list` 数量，从而改变一类买卖点（依赖中枢个数/背驰）与三类买卖点（依赖中枢位置）的结果。

## 4. 中枢与线段的双向绑定

中枢本身不知道自己属于哪个线段，是 [update_zs_in_seg](file:///workspace/KLine/KLine_List.py#L177-L204) 在每次 `cal_seg_and_zs` 末尾完成绑定：

1. 只处理尾部**未固化**的线段；
2. `zs.is_inside(seg)` 成立则 `seg.add_zs(zs)`；
3. 为每个中枢补 `bi_in / bi_out / bi_lst`；
4. 连续 3 个确定线段后，把更早线段的 `ele_inside_is_sure` 置 True，后续跳过。

`CZS.is_inside` 的判定是「中枢起始笔落在该线段的首尾笔区间内」（[ZS.py#L159-L160](file:///workspace/ZS/ZS.py#L159-L160)），因此一个中枢只会挂到一个线段上（段内算法下）。

## 5. 本篇小结

- 中枢区间 = 所有构成笔低点最大值 ~ 高点最小值；`peak_*` 是整体极值，两者不要混用；
- 中枢需要「两笔重叠」才成立，第 0 笔不能作为起点；
- `zs_combine_mode` 决定合并判据，合并后区间取并集并保留子中枢；
- `zs_algo` 决定中枢是否允许跨段，直接影响买卖点；
- 背驰判断 = 出笔必须突破中枢 + 出/入笔力度比 ≤ `divergence_rate`。
