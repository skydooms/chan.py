# 10 · 增量计算与策略开发

框架的核心能力之一：在已有结果上**逐根喂 K 线**，每次只重算尾部不确定部分，并返回「当下这一帧」的完整缠论结构。本篇讲清楚三种增量方式的差异、多级别喂数、快照、信号消失，以及策略/机器学习 demo 的完整流程。

## 1. 三种「推进方式」

| 方式 | 开关 | 数据来源 | 典型用途 |
| --- | --- | --- | --- |
| 一次性静态计算 | `trigger_step=False` | `DataAPI` | 离线分析、选股 |
| 回放 `step_load()` | `trigger_step=True` | `DataAPI` | 回测、动画 |
| 外部投喂 `trigger_load()` | 两种都可用 | 调用方自己给 | 实盘、合成 K 线、补当天数据 |

### 1.1 `step_load()`

[Chan.py#L120-L130](file:///workspace/Chan.py#L120-L130)：

```python
def step_load(self):
    assert self.conf.trigger_step
    self.do_init()                            # 清空，防止重复跑
    yielded = False
    for idx, snapshot in enumerate(self.load(self.conf.trigger_step)):
        if idx < self.conf.skip_step:
            continue
        yield snapshot                        # 每根最高级别 K 线 yield 一次
        yielded = True
    if not yielded:
        yield self                            # 一帧都没有时，至少返回自身
```

要点：

- `trigger_step=True` 时构造函数**不会**调用 `load()`（[Chan.py#L51-L53](file:///workspace/Chan.py#L51-L53)），必须显式调用 `step_load()`；
- 每次 yield 的是**同一个 `CChan` 对象**（不是拷贝）。如果你要把每帧结果保存下来，必须自己做 `copy.deepcopy(chan)`；
- `skip_step` 只影响返回，不影响内部计算（前面的帧仍会算）。

### 1.2 `trigger_load(inp)`

[Chan.py#L132-L151](file:///workspace/Chan.py#L132-L151)：

```python
chan.trigger_load({KL_TYPE.K_DAY: [klu1, klu2], KL_TYPE.K_30M: [klu...]})
```

| 规则 | 说明 |
| --- | --- |
| 入参 | `Dict[KL_TYPE, List[CKLine_Unit]]` |
| 最高级别必填 | 缺少 `lv_list[0]` 会抛 `CChanException(NO_DATA)` |
| 次级别可缺省 | 缺省的级别本次不喂数据 |
| 缓存 | 内部 `klu_cache` 保存「超过当前父 K 线时间」的次级别 K 线，等父级别推进后继续消费 |
| 时间校验 | 每根必须严格大于上一根（`KL_NOT_MONOTONOUS`） |
| 计算时机 | `trigger_step=True`：每根 klu 触发 `update_bi` → `cal_seg_and_zs`；`False`：全部喂完后统一 `cal_seg_and_zs` |

> 反复用 `trigger_load` 喂**同一批历史数据**是错误用法：它只做追加，不去重。重跑请新建 `CChan` 或从快照恢复。

### 1.3 重新计算的范围

增量模式不会全量重算，靠的是各模块的「安全位置」游标：

| 模块 | 游标 | 行为 |
| --- | --- | --- |
| 线段 | `last_sure_seg_start_bi_idx` | 从最后一个确定线段的起点之后重算（`cal_seg`） |
| 中枢 | `last_sure_pos` / `last_seg_idx` | 弹掉不安全中枢后重算（`CZSList.cal_bi_zs`） |
| 买卖点 | `last_sure_pos` / `last_sure_seg_idx` | 删除尾部买卖点后重算（`CBSPointList.cal`） |
| 笔 | 虚笔 `sure_end` | 每次先撤虚笔再推进 |
| 线段内中枢 | `ele_inside_is_sure` | 连续 3 个确定段后固化，不再重算 |

因此性能与「尾部长度」相关，而不是与总长度相关。

## 2. 从外部喂 K 线（实盘基础）

`Debug/strategy_demo2.py` 的最小骨架：

```python
config = CChanConfig({"trigger_step": True, "divergence_rate": 0.8, "min_zs_cnt": 1})
chan = CChan(code="sz.000001", data_src=DATA_SRC.BAO_STOCK,
             lv_list=[KL_TYPE.K_DAY], config=config)   # 此时不计算

                end_date=None, autype=AUTYPE.QFQ)

for klu in src.get_kl_data():
    chan.trigger_load({KL_TYPE.K_DAY: [klu]})
    bsp_list = chan.get_latest_bsp()          # 最新买卖点
    # ... 你的策略 ...
CBaoStock.do_close()
```

策略读取数据的常用姿势（与 demo 一致）：

```python
cur_lv = chan[0]
last_klc = cur_lv[-1]           # 最后一根合并K线
last_klu = last_klc[-1]         # 最后一根原始K线
prev_klc = cur_lv[-2]           # 倒数第二根（分型已确认的那根）

last_bsp = chan.get_latest_bsp(number=1)[0]
if last_bsp.klu.klc.idx == prev_klc.idx:   # 买卖点落在刚确认的分型上
    ...
```

> 为什么判断 `prev_klc` 而不是 `last_klc`？因为分型需要右侧一根 K 线才能确认（见 [02-K线与合并](02-K线与合并.md#44-分型判定-update_fx)），最新一根上的结构还不稳定。

## 3. 多级别喂数

### 3.1 一次性喂完次级别（推荐）

`Debug/strategy_demo4.py` 的技巧：

```python
kl_30m_all = list(data_src_30m.get_kl_data())
for idx, klu_day in enumerate(data_src_day.get_kl_data()):
    if idx == 0:
        chan.trigger_load({KL_TYPE.K_DAY: [klu_day], KL_TYPE.K_30M: kl_30m_all})
    else:
        chan.trigger_load({KL_TYPE.K_DAY: [klu_day]})
```

原理：`load_iterator` 的 `klu_cache` 会把「时间超过当前日线」的 30 分钟 K 线缓存起来，等日线推进时自动消费。这样调用方**不需要自己做时间对齐**。

### 3.2 小级别驱动大级别重算（合成 K 线场景）

`Debug/strategy_demo3.py` 的场景：实盘只拿到 15 分钟线，60 分钟线要自己合成，而「当前这根 60 分钟线」在下一分钟会变化，框架无法回退已喂入的 K 线。

解决方案：**快照 + 重放**

```python
chan_snapshot = CChan(...)          # 上一个「所有级别都已确定」的时刻
klu_15m_lst_tmp = []

for klu_15m in src_15m.get_kl_data():
    klu_15m_lst_tmp.append(klu_15m)
    klu_60m = combine_60m_klu_form_15m(klu_15m_lst_tmp)   # 合成未完成的 60M

    chan = copy.deepcopy(chan_snapshot)                    # 从快照重建
    chan.trigger_load({KL_TYPE.K_60M: [klu_60m],
                       KL_TYPE.K_15M: klu_15m_lst_tmp})
    # ... 策略 ...

    if len(klu_15m_lst_tmp) == 4:        # 60M 已完成，不再变化
        chan_snapshot = chan
        klu_15m_lst_tmp = []
```

代价是每根小级别 K 线都要深拷贝一次，性能开销大；完整版用 pickle 落盘快照来降低内存占用。

## 4. `is_sure`、当前帧与「信号消失」

- 框架每次返回的都是**当前帧**的结构，尾部元素可能 `is_sure=False`；
- 随着新 K 线到来，一类买卖点可能在多个 K 线位置「轮流出现」，最终只保留一个；
- 已确认（`is_sure=True`）的元素不会回改，`is_sure=False` 只可能出现在头尾；
- **走势多义性**：任一时刻只能给出一种结构，因此有些「事后成立」的买卖点在过程中可能一次都没被标记过。quick_guide 建议的缓解办法是「每根 K 线用两组不同参数各跑一次」。

策略层的义务：**自己判断当前买卖点是否值得交易**（背驰度、中枢数、成交量、模型打分……），框架只负责给出结构。

## 5. 快照：deepcopy 与 pickle

### 5.1 `copy.deepcopy(chan)`

`CChan` 自定义了 `__deepcopy__`（[Chan.py#L55-L83](file:///workspace/Chan.py#L55-L83)），流程：

1. 逐级别深拷贝 `CKLine_List`（其内部又深拷贝 `CKLine/klu/bi/seg/segseg/zs/bsp/指标模型`）；
2. 重建跨级别引用：`memo[id(klu)].sup_kl = memo[id(klu.sup_kl)]`，`sub_kl_list` 同理；
3. 若存在 `klu_cache` / `klu_last_t`（`trigger_load` 之后才有），一并深拷贝。

注意点：

- `CKLine_Unit.__deepcopy__` **故意不拷贝** `klc/sup_kl/sub_kl_list/pre/next`，避免图结构递归爆炸（[02](02-K线与合并.md#25-__deepcopy__-的特殊处理)）；
- 因此不要自己深拷贝单个 klu 期望得到完整关系，必须整体深拷贝 `CChan`；
- 深拷贝开销与「总 K 线数」成正比，不适合每帧都做（demo3 仅为演示）。

### 5.2 pickle 序列化

```python
chan.chan_dump_pickle("chan.pkl")
chan2 = CChan.chan_load_pickle("chan.pkl")
```

实现（[Chan.py#L313-L379](file:///workspace/Chan.py#L313-L379)）：

- `chan_dump_pickle`：
  1. 临时把递归上限提高到 `0x100000`；
  2. 把所有 `klu/klc/bi/seg/segseg` 的 `pre/next` 置空（避免循环引用导致递归溢出）；
  3. `pickle.dump(self)`；
  4. 恢复递归上限，并调用 `chan_pickle_restore()` 把当前对象的关系链重建回来。
- `chan_load_pickle`：`pickle.load` 后对**新对象**调用 `chan_pickle_restore()`。

`chan_pickle_restore` 按列表顺序重建双向链表（klu、klc、bi、seg、segseg 五类），因此**不要手工打乱 `lst` 顺序**，否则恢复出的 `pre/next` 会错。

> 小缺陷：`chan_dump_pickle` 没有 `try/finally`，如果 `pickle.dump` 抛异常，当前对象的 `pre/next` 会保持被置空的状态。生产代码建议先深拷贝再 dump，或自己包一层 `try/finally`。

如果遇到 `RecursionError`，除了上面的 API，也可以全局 `sys.setrecursionlimit(0x100000)`（quick_guide 的推荐做法）。

## 6. 两种模式的一致性

quick_guide 明确承诺（也是设计目标）：

> 给定同样范围的 K 线，**静态一次性计算**与**逐根增量计算**的最终状态应当完全一致；不一致即为 bug。

实现上通过「每次推进都先撤虚笔/回滚不安全尾部，再重算」保证。实际验证方式：

```python
# 静态
c1 = CChan(code="...", config=CChanConfig({}), lv_list=[KL_TYPE.K_DAY], ...)

# 增量
c2 = CChan(code="...",
           config=CChanConfig({"trigger_step": True}), lv_list=[KL_TYPE.K_DAY], ...)
for _ in c2.step_load():
    pass

assert len(c1[0].bi_list) == len(c2[0].bi_list)
assert len(c1[0].seg_list) == len(c2[0].seg_list)
assert len(c1[0].zs_list) == len(c2[0].zs_list)
```

> 注意 `step_load()` 是生成器，必须消费完（`for _ in ...: pass` 或 `list(...)`）才会跑完整个数据集。

## 7. 防未来函数

- `trigger_load` 每次只把「当前时刻已有的 K 线」交给框架，框架内部**不会**访问未来数据；
- 只要你在下一次 `trigger_load` 之前完成判断，就不存在未来信息；
- 反例：
  - 先一次性喂完全部 K 线，再回头「逐帧」调用策略 → 已经拿到未来数据；
  - 用静态模式算完整个区间，再把 `get_latest_bsp(number=0)` 全量列表当作「当时可知」的信号；
  - 在策略里访问 `chan[0].seg_list[-1].eigen_fx` 等可能由后续 K 线才确定的对象，却不检查 `is_sure`。

推荐检查清单：

1. 每帧只读当前帧对象；
2. 只对 `is_sure=True` 或「刚确认一根」的元素做交易决策；
3. 若使用模型打分，确保特征在离线/在线两条路径上一致（本项目只保留容器 `CFeatures`，一致性校验框架属于完整版）。

## 9. 一个可用的策略骨架

```python
import copy
from Chan import CChan
from ChanConfig import CChanConfig
from Common.CEnum import AUTYPE, BSP_TYPE, DATA_SRC, FX_TYPE, KL_TYPE
from DataAPI.MyAPI import CMyApi

config = CChanConfig({
    "trigger_step": True,
    "divergence_rate": 0.8,
    "min_zs_cnt": 1,
    "bs_type": "1,2,3a",
    "print_warning": False,
})

chan = CChan(code="sz.000001", data_src="custom:MyAPI.CMyApi",
             lv_list=[KL_TYPE.K_DAY], config=config, autype=AUTYPE.QFQ)

CMyApi.do_init()
try:
    for klu in CMyApi(...).get_kl_data():
        chan.trigger_load({KL_TYPE.K_DAY: [klu]})

        cur = chan[0]
        if len(cur) < 3:
            continue

        bsps = chan.get_latest_bsp(number=1)
        if not bsps:
            continue
        bsp = bsps[0]

        # 1) 必须是刚确认的分型
        if bsp.klu.klc.idx != cur[-2].idx:
            continue
        # 2) 只做一类买卖点
        if BSP_TYPE.T1 not in bsp.type and BSP_TYPE.T1P not in bsp.type:
            continue
        # 3) 背驰度过滤
        if bsp.features["divergence_rate"] > 0.8:
            continue
        # 4) 分型方向与买卖方向一致
        if bsp.is_buy and cur[-2].fx != FX_TYPE.BOTTOM:
            continue
        if (not bsp.is_buy) and cur[-2].fx != FX_TYPE.TOP:
            continue

        price = cur[-1][-1].close
        # do_trade(bsp, price)
finally:
    CMyApi.do_close()
```

## 10. 增量模式的性能注意事项

| 建议 | 原因 |
| --- | --- |
| 不要每帧 `deepcopy` | 开销与历史长度成正比；仅在「必然不再变化」的时刻做快照 |
| 次级别一次性喂完 | 避免自己写时间对齐逻辑，也减少 `trigger_load` 调用次数 |
| 批量扫描时关闭 `print_warning` | 大量股票会产生海量日志 |
| 不需要的指标不要开 | `cal_demark` / `cal_rsi` / `cal_kdj` / `mean_metrics` / `trend_metrics` 都会逐 K 线的增量开销 |
| 不理解结构时不要关 `kl_data_check` | 关闭后时间错位不会报错，但结果不可信 |
| 用 `make_cache` 思路写自定义指标 | 本项目所有热点取值都按实例缓存，冲突时记得 `clean_cache()` |

## 11. 本篇小结

- 三种推进方式：静态、`step_load`、`trigger_load`；
- `step_load` 返回同一个对象，需要留存就深拷贝；
- 多级别喂数交给框架的 `klu_cache` 做时间对齐，不要自己切；
- 合成 K 线场景用「快照 + 重放」，不要试图修改已喂入的 K 线；
- 买卖点会消失，策略必须以当前帧 + `is_sure` 为准；
- pickle 会临时置空 `pre/next`，注意异常路径。
